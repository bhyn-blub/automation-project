# Future Features

Status: Draft
Version: 1.0
Last Updated: 2026-07-26
Owner: Bhyn

## Purpose

Define the long-term product roadmap after Version 1.

This document prevents future ideas from being added into the MVP while ensuring valuable opportunities are not forgotten.

---

# Roadmap Philosophy

Build in stages.

```text id="roadmap1"
V1 → Validate
V2 → Improve
V3 → Grow
V4 → Scale
```

Each stage should only begin after the previous stage is stable.

# Prioritization Rules

A future feature should only be built if:

1. Users request it repeatedly.
2. It solves a significant problem.
3. It aligns with the product vision.
4. It does not compromise platform simplicity.

---

# Success Metrics Before Moving Versions

## Move From V1 → V2

Requirements:

✓ Stable platform

✓ Active users

✓ Core workflows validated

---

## Move From V2 → V3

Requirements:

✓ Proven demand for industry modules

✓ Template adoption

✓ Strong retention

---

## Move From V3 → V4

Requirements:

✓ Large customer base

✓ Third-party integration demand

✓ Workflow complexity exceeds current system

---

# Long-Term Vision

The long-term goal is not to build:

```text id="visionbad"
A tuition app

A CRM

A task manager
```

The long-term goal is to build:

```text id="visiongood"
A modular operational platform

that can be configured for

students,
teachers,
tuition centres,
freelancers,
small businesses,
and future industries.
```
